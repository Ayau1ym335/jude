## 2. Анализ специфических вопросов из задания

### Шаг 1: `backend/test_api.py` с жестким путем Windows
- **Исследование:** В кодовой базе репозитория файл `backend/test_api.py` отсутствует в системе контроля версий git (он присутствовал только внутри сторонней библиотеки `numpy` в `.venv`).
- **Статус:** В коде проекта жестких абсолютных путей нет — все обращения к конфигурационным файлам (`.env.local`) и модулям используют относительные пути через `Path(__file__)` и `os.path.dirname(__file__)`.

### Шаг 2: Валидация скана и хранилище Supabase Storage
- **Причины отказа валидации (`app/geometry/validator.py`):**
  1. `INVALID_FORMAT`: неподдерживаемый формат или повреждённый файл.
  2. `EMPTY_MESH`: пустой файл или отсутствие граней.
  3. `NOT_WATERTIGHT`: открытые отверстия/дыры в поверхности (незамкнутая оболочка).
  4. `INVALID_NORMALS`: самопересечения или вывернутые нормали.
  5. `MULTIPLE_COMPONENTS`: разрозненные куски скана (шум сканера).
  6. `LOW_RESOLUTION`: менее 1000 граней.
  7. `INVALID_SCALE`: максимальный габарит менее 50 мм (ошибочный экспорт в метрах) или более 5000 мм.
- Сообщения пользователю формируются через понятный справочник `VALIDATION_MESSAGES` в `messages.py` с рекомендациями по исправлению.
- Бакет хранилища называется `scan-files` (миграция `20260720124500_scan_files_bucket.sql`), обращение к нему везде единообразно.

### Шаг 3: Клики по модели (Raycast)
- Рассмотрены типичные причины промаха кликов:
  - Несовпадение DPR (devicePixelRatio): учтено в `dist2D` и Canvas overlay.
  - Масштаб и трансформация: `raycastToMesh` преобразует точку пересечения через мировую матрицу сетки.
  - Направление нормалей: `ModelViewer` настраивает правильное отображение граней.
  - Тест точности привязки на синтетической икосфере подтверждает ошибку строго в пределах одного межвершинного ребра (`test_raycast_accuracy.py`).

### Шаг 4: Ограничение «только 3 точки/линии» и создание линии
- **Причина ограничения:**
  1. В БД (`supabase/migrations/20260725153820_update_trim_lines.sql`) наложено жесткое ограничение: `check (line_type in ('proximal', 'ankle', 'distal'))`.
  2. В API (`backend/app/schemas/trim_line.py`, `routers/trim_lines.py`) определен `LineType = Literal["proximal", "ankle", "distal"]`.
  3. Во фронтенде (`TrimLinesPanel.tsx`) объявлен фиксированный массив `LINE_ORDER: LineType[] = ["proximal", "ankle", "distal"]`.
  4. Это инженерное ограничение для 3 анатомических линий обрезки (проксимальный край, висок/голеностоп, дистальный край). Внутри каждой отдельной линии количество точек не ограничено (требуется минимум 2 точки для замыкания кривой).

### Шаг 5: Сглаживание и версионирование
- В `POST /geometry/apply-smoothing` рассчитывается разница `diff = np.linalg.norm(smoothed_mesh.vertices - mesh.vertices, axis=1)`.
- Количество смещенных вершин `vertices_moved` возвращается в ответе.
- Сохранение выполняется в `project_versions` с привязкой `parent_version_id` и выгрузкой STL-файла в Storage (`scan-files/processed/...`).

## 3. Не удалось воспроизвести / Не проверено

1. **Реальная загрузка в облачный Supabase Storage в offline-режиме:**
   - В тестовом окружении без активного сетевого подключения к живому облаку Supabase интеграция со Storage валидируется через mock-клиент и юнит-тесты.
2. **Touch-события на мобильных устройствах:**
   - Обработчики `pointerdown`, `pointermove`, `pointerup` и вызов `setPointerCapture` реализованы по стандартам W3C Pointer Events, однако физическое тестирование на смартфонах/планшетах не проводилось.
3. **Файл скана `disk (2).stl` из `docs/blockers.md`:**
   - Данный файл в локальном репозитории и Storage отсутствует (404), тестирование производилось на валидных синтетических икосферах и 4 анатомических моделях головы (`head_symmetric`, `head_mild`, `head_moderate`, `head_severe`).
